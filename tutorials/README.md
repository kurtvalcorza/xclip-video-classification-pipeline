## Conformance notes

- **Standalone carrier (NOTEBOOK_SPEC 2.0 §4):** the primary path performs no clone, repository install, or repository import. Section 2 is `src/xclip_video_classification_pipeline/pipeline.py` verbatim (tagged `metadata.dimer.embedded_module`; the only rewrite makes the default weights directory working-directory-relative), Section 3 carries the model identity and the 9-file SHA-256 manifest inline and asserts they agree with the module before anything is fetched, and Section 1 carries the exact `pyproject.toml` runtime pins. `metadata.dimer.generated_from` records the repository, the generating revision, the module's SHA-256, and the generator version.
- **Parity (PAR1–PAR3):** `tests/test_notebook_parity.py` and `tools/validate_release_assets.py` fail when the carried module, the inline manifest, or the inline pins differ from the repository, or when the notebook is not byte-identical to the generator's output.
- **Model acquisition (MOD1–MOD8):** `stage_missing_files(WEIGHTS_DIR, allow_download=True)` fetches only the manifest entries that are absent, from the Hugging Face Hub at the immutable revision (never `main`); `verify_snapshot` re-hashes every entry; `from_pretrained(weights_dir=WEIGHTS_DIR)` loads the verified files with `local_files_only=True` and `trust_remote_code=False` through `XCLIPModel`/`XCLIPProcessor`, calling the image processor and tokenizer explicitly because the pinned processor's `videos=` keyword yields no pixel values. The upstream `pytorch_model.bin` is not listed and not used; the notebook's only external dependencies are the pinned PyPI distributions and the Hub at the model revision.
- **Role stages:** `validate_inputs` writes `outputs/xclip_video_classification_input_manifest.json` with the schema (8 frames, resize/centre-crop, softmax rule), the ceilings, each clip's observed frame count, mode and size, the normalised label set, the verdict, and one recorded rejection finding from the three-frame probe; `evaluation_report` writes `outputs/xclip_video_classification_evaluation_report.json` — `sample-sanity` with `top1_accuracy`, the `chance` baseline and one entry per clip (top-1, its probability, the correct name and its rank) on the synthetic clips; `not-measurable` on BYOD (with what labelled data would make the task measurable).
- The default sample is five deterministic 8-frame cartoon clips drawn in code with Pillow (no text rendering, so their digests are stable across Pillow builds) with the five class names they were drawn to depict — the same clips the smoke run used; `top1_accuracy` against intentions you drew yourself is sanity evidence for the input contract, preprocessing, forward pass and softmax, not a video-classification metric. **Four of the five clips are recorded misses** (the smoke run ranked `a ball standing still` first for every clip; 1/5 at chance 0.2): a Kinetics-trained model does not read drawn motion, and the notebook says so rather than tuning the clips until they pass.
- Score semantics (UNC1–UNC4): the probabilities are a softmax over the caller's label set — a ranking, not a calibrated probability — and the model never abstains; the notebook says so before the first ranking and again in the interpretation section, states that the label set is part of the request (the same clip ranked `juggling balls` at 0.98 under Kinetics-style names), and states that blank frames still yield a confident top-1. The label set is the caller-owned request parameter (the BYOD form field; the synthetic path's five names) and is passed explicitly on every `classify` call. The notebook performs no validation of its own — clips and names are checked only by the pipeline's `validate_inputs`/`classify` path.
- Ceilings `NUM_FRAMES` (8), `FRAME_SIZE` (224), `MIN_IMAGE_SIDE` (16), `MAX_IMAGE_SIDE` (4096), `MIN_LABELS` (2), `MAX_LABELS` (32), `MAX_LABEL_CHARS` (64) and `MAX_TEXT_TOKENS` (77) are printed before the model runs.
- CPU is documented as adequate (card-measured 5.2 s load, 0.36 s for the first clip and 0.11 s per clip thereafter with five names; 1.3 s for eight 4096×4096 frames); the notebook states that cost is per clip and that GPU rankings need not match CPU rankings on close pairs.
- `USE_BYOD` defaults to `False` so the sample path never opens an upload dialog.
- `tools/validate_release_assets.py` performs source validation only. It does not satisfy the
  clean-runtime execution requirement; a release review must confirm that a recorded clean run in
  `docs/release-verification.md` matches the notebook revision under review before the status is
  promoted to `Release-grade`.
