# X-CLIP tutorial: pre-registered validation grid, fresh test and reading rule

Committed on its own, before any grid run of this protocol and before any score on the fresh test (owner rulings
R113-D1 and R113-D2, 2026-10-17; fleet SCORE_ONCE_RULE items 1–8). Nothing below may be changed in response to a
fresh-test number. The code that implements it is `src/xclip_video_classification_pipeline/protocol.py` and
`samples.fetch_fresh_test`.

## 1. Why this exists (disclosure)

The default recipe (lr 1e-5 × 8 epochs, batch 16) was fixed on 2026-09-20 after a CPU sweep on the default
181 / 53 / 66 split that read the **test** scores of all five learning-rate arms (2e-5, 5e-5 and 1e-4 for 10 epochs;
1e-5 and 5e-6 for 8 epochs) before fixing lr 1e-5 × 8 (`docs/release-verification.md`, row of 2026-09-20). Validation
scores were recorded for the chosen arm only; `BATCH_SIZE = 16` and seed 0 have no recorded selection. The 66 test
clips are therefore the **exposed development test**: shown for continuity, labelled as such, and never used to decide.

## 3. The validation grid (R113-D2)

- Configurations: lr ∈ {**1e-5** (C0, default), **5e-6** (C1), **2e-5** (C2)}, each for 8 epochs; everything else in §2 fixed.
- Score per configuration: the kept-epoch validation top-1, counted in clips of the 53.
- Selection: C0 stays unless a challenger beats it by at least two clips (0.038; a practical tolerance, not a
  significance threshold). Ties and smaller wins go to the default. If both challengers clear C0, the one with more
  correct clips wins; equal counts go to the smaller learning rate.
- The grid records validation only and never scores the fresh test (SCORE_ONCE_RULE 4). The selected run is kept in
  memory as trained (no re-training) and identified by the SHA-256 of its head tensors.

## 4. The fresh test (R113-D1)

- Source: every HMDB51 split-1 **training** clip of the same ten classes at the same revision:
  `default/train/0000.parquet` (380,572,368 bytes, 1,190 rows), row groups 0–2 (700 ten-class clips). Pins are
  SHA-256 over each row group's video bytes + label, as `ROW_GROUP_PINS`:
  - row group 0: `2d0459984a029ca69a39a13ebdafcd387d264601970b9b0197e6c8df8d2ab210`, 114,923,824 bytes
  - row group 1: `6bcc4700ffc1f3541a802af5bd68a0f0c02d1335ecc057e0ec0b662cfe777069`, 101,805,360 bytes
  - row group 2: `f720253403970c478941585b93bbc63cbf3f1919a1daacf88216cb3f17df6eef`, 83,889,668 bytes
- Exclusion by film: a clip is dropped when its film, under the strict key (source-video name case-folded, trailing
  `_<n>` part suffixes stripped), appears among the 300: 8 films / 18 clips (`basketball_dribbling_tips_`,
  `chewing_gum`, `finding_forrester`, `how_to_do_a_cartwheel`,
  `projekt_spoho_2008_-_27_02_08_-_training-_bodenk_r`, `return_of_the_king`, `theboondocksaints`, `treppensteigen`).
  Path overlap with the 300: 0. AVI-byte SHA-256 overlap: 0.
- Near-duplicate screen against the 300, fresh test hidden (no model loaded, nothing scored), run 2026-10-18:
  - exact: decoded-pixel `clip_digest` of the 8 sampled frames: **0** matches;
  - perceptual: 64-bit dHash per sampled frame; a pair is a candidate when at least 4 of a fresh clip's 8 frames
    have a frame of a used clip within T bits. **T = 11** was set before screening as the 95th percentile of the
    nearest-frame distance over 2,880 synthetic copies of 60 seeded clips of the 300 (head and tail trimmed by 10 %,
    JPEG q40, brightness × 1.15, rescale 0.8, 5 % crop; median 1, 90th percentile 9, max 27 bits). It was not set on outcomes.
  - 217 candidate pairs (94 fresh clips) were checked by content. The mean absolute grey difference of matched
    thumbnails is 18.4–101.9 (0–255 scale), and the 8 closest pairs were inspected frame by frame. They show
    different films, actions and scenes (climbing vs dribbling, two different iaido katas, and so on). **No hit was
    confirmed; the screen removed 0 clips.** Calibration read: 30 of 44,307 cross-film pairs inside the 300 are
    candidates too (dHash is loose on dark, static frames), which is why candidates are confirmed by content.
  - All 682 clips decode with PyAV (one AVI carries non-UTF-8 metadata tags; `decode_clip` ignores tag-decoding
    errors, pixels unaffected).
- Result: **682 clips**; per class brush_hair 70, cartwheel 67, catch 68, chew 68, clap 70, climb 69, climb_stairs 66,
  dive 68, draw_sword 68, dribble 68 (every class ≥ 50, so no stop condition).
- Pin: the per-clip list in Appendix A (row group, index in row group, path, AVI bytes, AVI SHA-256). The SHA-256 of
  its text (`samples.fresh_clip_list_digest`) is **`ac0144fa7c33b06ec11ce73b560eaf339ea0c9c70dd934493ca4303019a4bc04`**
  (`FRESH_TEST_LIST_SHA256`). The fetch is refused on any row-group, list or count mismatch.
- Exposure that remains: X-CLIP was trained on Kinetics-400, whose vocabulary covers most of the ten actions, and
  video-level overlap with Kinetics cannot be ruled out (DAT9); the fresh clips share that exposure.

## 5. Score-once rule

- The fresh test is scored only when every setting in §2 holds, the grid of §3 ran complete on this run's data and
  settings, the lr in use is the grid's selection, and the head in memory is the selected run (head SHA-256). Any
  difference is **exploratory**: validation and the exposed development test only, written to `*_exploratory_<n>`.
- A later run in the same runtime with identical settings is a **reproduction** (`*_reproduction_<n>`); nothing
  overwrites the first report. Reports carry `test_look`, `preregistered` and `settings_differing`.
- CPU development checks run with the fresh test masked (`DIMER_MASK_FRESH_TEST=1`). The first hosted T4 run with
  these settings is the evaluation of record; `protocol.RECORDED_EVALUATION` stays `None` until then.

## 6. Reading rule

1. The paired selected-minus-frozen top-1 difference on the same fresh clips (the selected system is the grid's
   selected run, or the frozen model if it was kept).
2. A 95 % percentile bootstrap interval resampling **films** (strict key) with replacement: n_boot = 2000,
   seed = 113.
3. McNemar discordant counts (frozen-only correct, selected-only correct) with the exact two-sided p.
4. Read **"adapted helps"** only if the interval excludes 0 (lower bound > 0); otherwise **"no demonstrated gain"**
   (and "adapted is worse" if the upper bound is < 0).
5. Top-3 accuracy, macro F1 and per-label recall are descriptive. The majority baseline is an expected value over
   a random tie-break.
6. The 66 exposed clips are reported once, labelled "exposed development test", and never decide.
